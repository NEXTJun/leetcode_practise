# 練習操作流程

教學原則以 [AGENTS.md](../AGENTS.md) 為準。本文件定義指令行為，所有程式路徑均以專案根目錄為基準。

## 常用指令

| 指令 | 要完成的動作 | 回覆界線 |
|---|---|---|
| 下一題 / `next` | 清空 `main.go` 成基本框架，依進度選未完成題，更新交接 | 只給題目、限制、例子與第一個引導問題 |
| 框架 / `scaffold` / `template` | 放好當題函式簽名、必要型別、範例呼叫與 TODO | 不填演算法；思路確認正確時可直接執行 |
| 檢查 / `check` | 先讀 `main.go`，檢視方向、控制流程、邊界與 helper | 提示級建議與必要反例，不修改作答 |
| 批改 / `review` / `grade` | 先讀 `main.go`，檢查編譯與邏輯，適合時執行範例及針對性案例 | 指出錯誤、反例與修正方向，不重寫完整解法 |
| 紀錄 / `record` / `save` | 保存原始作答、整理歸檔、更新進度，完成後直接下一題 | 不需要再詢問是否切題 |
| 只紀錄 / `record only` | 同上，但保留 `main.go` 與當前題目 | 停在已歸檔狀態 |
| 清空 main / `clear main` | 只清空 `main.go` 成基本框架，交接註明已清空 | 同時要求下一題時才切題 |
| 直接給解答 / 幫我實作 | 提供或實作完整解法；編輯前保留已有原始作答 | 補充正確性、複雜度與關鍵邊界 |

## 框架與切題

基本空框架：

```go
package main

func main() {
}
```

Scaffold 可使用明確的 `panic("TODO")` 作為待實作函式內容，避免假回傳值被當成正解；範例應標示預期結果。已有實作時只補必要結構，不抹除作答。

使用者明確要求下一題或清空即授權重設 `main.go`；這不代表未完成題已解完。依需要在交接或總表保留未完成狀態。切題依已完成題型與卡點決定；指定題目優先，避免把已解題誤當新題。

## 紀錄的完成條件

1. 修改或清空前讀取完整 `main.go`，將原文保存至當題 `my_attempt.md`；原始區塊不格式化、不修正。已有作答紀錄時追加版本，不覆蓋舊原文。
2. 依 [模板](TEMPLATE.md) 更新 `summary.md` 與 `final_solution.go`。最終答案與原始作答分開，日期、口述思路及驗證結果須有依據。
3. 在 [總表](RECORD.md) 新增或更新當題狀態。未完成但要求保存時仍可紀錄，標為 `Solving` 或 `Revisit`，不捏造通過結果。
4. 確認三份歸檔存在、原始碼完整且總表一致後，才執行預設切題。`record only` 保留目前作答。
5. 更新 [交接](SESSION_HANDOFF.md)：當前題目、階段、已確認思路、卡點、下一步與驗證摘要。

解題完成時也要同步上述歸檔與進度；只有使用者要求「紀錄」或「下一題」才依相應指令自動切題。歸檔出錯時保留 `main.go`，回報未完成的步驟。

## 日期日誌與久別接續

- 練習日結束、使用者要求總結，或跨日再次開始時，按 [練習日誌](PRACTICE_LOG.md) 的格式追加或更新當天節次；同一天不重建已寫的節。記實際做過的題型、驗證、能力觀察、待複習與下次第一步。
- 新對話先讀 [交接](SESSION_HANDOFF.md) 並核對 `main.go`，再看日誌最新一節。依日誌的間隔與表現做短診斷；是否重練基礎由實際能力決定，不因時間經過就清空進度。
- 日誌不代替每題歸檔、[總表](RECORD.md) 或交接；更新任何一處時，題號、日期與狀態要保持一致。無法確認的日期、掌握程度或驗證結果標示未知。

## 批改與驗證

先處理會阻止執行或改變答案的問題，使用最小反例說明；風格建議放在正確性之後。測試原地修改輸入的解法時，每個案例使用新的輸入資料。

針對題目限制選擇一般與邊界案例，例如單一元素、重複值、偏斜樹或全相同格子。區分限制內必須處理與限制外的延伸討論。完整收尾應包含正確性理由及額外空間分析（含遞迴堆疊，說明是否計入輸出）。

交接只記錄實際做過的驗證與仍待確認之處，不將一次範例輸出或 AI 整理的答案當成使用者已獨立掌握。

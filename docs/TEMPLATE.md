# 每題紀錄模板

檔案放在 `solved/<四位題號>_<英文_slug>/`（相對於專案根目錄）。作答歷史與題目解法留在同一目錄，共用模板集中於 `docs/`。

```text
solved/0001_two_sum/
├── my_attempt.md
├── summary.md
└── final_solution.go
```

## my_attempt.md

- 作答／保存日期：使用已知日期；不知道原始作答時間時標示未知。
- 原始作答：以 Go 程式碼區塊完整保留當時 `main.go`，包含 imports、main、helper、註解及錯誤；不修正或重新排版。
- 原本思路：優先記錄使用者的口述；僅從程式推斷時標示「依程式推測」，沒有資訊則標示未提供。
- 優點：指出具體正確觀察或實作。
- 問題與反例：記錄錯誤原因、失敗輸入與預期結果。
- 重做時：追加新日期與完整作答，保留先前版本。

## summary.md

- 題目：題號、名稱、難度、輸入輸出與關鍵限制。
- 最終作答：已完成時放最終 Go 程式碼，須與 `final_solution.go` 對應；未完成則註明狀態。
- 解法推導：暴力解瓶頸、關鍵觀察、資料結構或狀態定義。
- 正確性理由：迴圈不變量、遞迴定義或適合本題的論證。
- 改進：從使用者原始作答到最終作答的差異。
- 複雜度：定義 n/m/h 等變數，列出時間、額外空間與遞迴堆疊，說明是否計入輸出。
- 邊界案例與驗證：輸入、預期、實際結果；區分人工推導、執行通過與尚未驗證。
- 面試口述版：簡短說明核心想法、正確性及複雜度。
- 待複習：使用者尚未能獨立說明的部分，不把 AI 提供的總結當成使用者口述。

## final_solution.go

只保存最終 Go 解法，保留該題所需的型別與 helper，方便快速複習。這是歸檔，不保證可單獨執行；需要可測試版本時另建立正式 `problems/` 題目。

未完成但要求紀錄時，可用註解標明「尚無已確認的最終解法」，不放未驗證程式冒充正解。對應的總表狀態也不可標成 `Solved`。

保存與切題流程見 [WORKFLOW.md](WORKFLOW.md)。
